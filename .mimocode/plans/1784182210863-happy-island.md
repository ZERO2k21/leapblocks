# Plan: Add Missing ML Environment Features to NEURA

## Overview
Add 4 missing features to match PictoBlox's ML Environment: Local Image Dataset, Standalone Evaluate Tab, Model Export, and Full Hyperparameter Controls.

---

## Feature 1: Local Image Dataset (Download Tab)

**What**: Add a "Download" sub-tab in Collect mode. Images are stored locally in `public/assets/neura-datasets/` as organized folders. Users browse categories, select quantity, and images are fetched from the local folder (via relative URLs) and added to their project class as base64 samples.

**Architecture**:
```
public/assets/neura-datasets/
  animals/
    cat/
      cat_01.jpg ... cat_10.jpg
    dog/
      dog_01.jpg ... dog_10.jpg
    bird/
      bird_01.jpg ... bird_10.jpg
  vehicles/
    car/
      car_01.jpg ... car_10.jpg
    bicycle/
      bicycle_01.jpg ... bicycle_10.jpg
  food/
    apple/
      apple_01.jpg ... apple_10.jpg
    banana/
      banana_01.jpg ... banana_10.jpg
  objects/
    cup/
      cup_01.jpg ... cup_10.jpg
    book/
      book_01.jpg ... book_10.jpg
```

**Manifest file**: `src/neura/data/imageDatasets.ts` — JSON manifest listing all categories, subcategories, image counts, and preview thumbnails. This is a TypeScript constant, not fetched from an API.

**How it works**:
1. User opens Collect mode → sees Camera | Upload | **Download** tabs
2. Clicks Download → sees category grid (Animals, Vehicles, Food, Objects, etc.)
3. Selects a category → sees subcategories (e.g., Animals → Cat, Dog, Bird)
4. Selects subcategory + quantity (5, 10, 15, 20) → clicks "Add to Class"
5. Images are fetched from `/assets/neura-datasets/{category}/{subcategory}/{filename}.jpg`
6. Each image is converted to base64 via canvas and added as a Sample to the selected class
7. Progress bar shows during fetch/convert

**Files to modify**:
- `src/neura/ui/panels/ObjectDetectorPanel.tsx` — Add Download tab in `renderCollectMode()`
- `src/neura/ui/panels/ImageClassifierPanel.tsx` — Add Download tab (if applicable to image classifier)

**New files**:
- `src/neura/ui/components/ImageDatasetBrowser.tsx` — Browseable UI component
- `src/neura/data/imageDatasets.ts` — Dataset manifest (categories, paths, counts)
- `public/assets/neura-datasets/` — Actual image files (curated public domain photos)

**Note**: Initial dataset will use ~50-100 curated public domain images across 8-10 categories. Images should be small (200-400px) to keep bundle size reasonable. Can be expanded later.

## Feature 2: Standalone Evaluate Tab

**What**: Add an "Evaluate" mode (5th tab for object detection) showing model quality metrics after training.

**Files to modify**:
- `src/neura/hooks/useNeuraProject.ts` — Add `'evaluate'` to `ClassifierMode` type union (line 17)
- `src/neura/ui/ProjectWorkspace.tsx` — Add "Evaluate" to ModeSwitcher (line 28-30) and sidebar stepper (line 294-319)
- `src/neura/ui/components/WorkflowIndicator.tsx` — Add evaluate step between Train and Test
- `src/neura/ui/panels/ObjectDetectorPanel.tsx` — Add routing for `'evaluate'` mode (line 802-810)

**New file**:
- `src/neura/ui/panels/EvaluatePanel.tsx` — The evaluate view

**Evaluate Panel contents**:
1. **Per-class metrics table**: Class name, TP, FP, FN, Precision, Recall, F1 — styled table with color-coded bars
2. **Confusion matrix**: NxN grid with intensity coloring
3. **Overall summary cards**: Mean Precision, Mean Recall, Mean F1, Total detections
4. **Weak class alerts**: Highlight classes with F1 < 0.5
5. **Re-train button**: Quick link back to Train mode

**Data**: Run inference on each training sample, compute IoU against ground-truth annotations to get TP/FP/FN per class.

## Feature 3: Model Export

**What**: Add export buttons in Test mode to package the trained model for deployment.

**Files to modify**:
- `src/neura/ui/panels/ObjectDetectorPanel.tsx` — Add export section in `renderTestMode()`

**New file**:
- `src/neura/ml/ModelExporter.ts` — Handles model packaging and download

**Export formats**:
1. **JSON Model** — Self-contained JSON with class mappings, KNN feature vectors, weights
2. **TF.js** — model.json + binary weight shards
3. **ONNX descriptor** — Structured JSON for conversion pipelines
4. **TFLite descriptor** — Structured JSON for conversion pipelines

**Constraint**: NEURA uses MobileNet (frozen) + KNN, not a trainable neural net. True binary .tflite/.onnx requires Python tools. Our export produces structured data files.
