# Costume Editor — Add 5 Missing Features

## Summary
Add Camera Capture, Bitmap/Vector Mode Toggle, Reshape Tool, Rotation Center, and Eyedropper to the Paint Editor.

---

## Feature 1: Camera Capture

**Goal:** Allow users to capture a live photo via webcam and set it as a costume.

**Files to modify:**
- `leaplab_frontend/src/components/PaintEditor.tsx` — add camera modal UI + capture logic
- `leaplab_frontend/src/stage/CostumesTab.tsx` — add "Camera" option to bottom action buttons

**Approach:**
1. Add a `CameraCaptureModal` component inside PaintEditor.tsx (or a separate file if >100 lines):
   - Uses `navigator.mediaDevices.getUserMedia({ video: true })` to start webcam stream
   - Renders a `<video>` element with live preview
   - "Capture" button grabs a frame via an offscreen `<canvas>`, converts to dataURL
   - "Use Photo" confirms and loads the captured image into the Fabric.js canvas via `loadSrcToCanvas()`
   - "Cancel" stops the stream and closes the modal
2. Add a Camera icon (from lucide-react: `Camera`) to the ActionMenu in the left sidebar and to CostumesTab's bottom buttons
3. Add state: `[isCameraOpen, setIsCameraOpen]` in PaintEditor

**Key details:**
- Request camera with `{ video: { width: 800, height: 600 } }` for good resolution
- On capture: draw video frame to offscreen canvas → `toDataURL('image/png')` → `loadSrcToCanvas(dataUrl, 'Camera Capture')`
- Stop all tracks on modal close to release camera
- Handle permission denied gracefully with an error message

## Feature 2: Bitmap/Vector Mode Toggle

**Goal:** Two editing modes — Bitmap (pixel-based painting) and Vector (shape-based, current Fabric.js mode).

**Files to modify:**
- `leaplab_frontend/src/components/PaintEditor.tsx` — main implementation

**Approach:**
Add a `bitmapMode` state (`'vector' | 'bitmap'`). The UI toggle sits in the top toolbar area.

### Vector Mode (default, current behavior)
- Fabric.js canvas with shape objects, PencilBrush paths, etc.
- No changes needed here

### Bitmap Mode
When switching from Vector → Bitmap:
1. Flatten all Fabric.js objects to a single bitmap: `canvas.toDataURL()` → load into an HTML5 Canvas overlay
2. Hide the Fabric.js canvas (or make it non-interactive)
3. Show a native `<canvas>` element on top for pixel editing
4. Bitmap tools:
   - **Pencil**: Draw pixels directly using canvas 2D context (`lineTo` with `strokeStyle`)
   - **Eraser**: Same as current eraser logic (globalCompositeOperation 'destination-out')
   - **Fill**: Flood-fill algorithm (already exists in BG removal code — reuse the BFS approach)
   - **Brush size**: Use existing `strokeWidth` state

When switching from Bitmap → Vector:
1. Capture the bitmap canvas as a dataURL
2. Load it as a single `fabric.Image` on the Fabric.js canvas
3. Hide the bitmap canvas, show Fabric.js canvas

### UI Changes
- Add a toggle button in the top toolbar: "Bitmap | Vector" pill toggle
- When in bitmap mode, the tool panel shows only: Pencil, Eraser, Fill, Select (simplified)
- When in vector mode, show all current tools

### New state/refs needed
- `[editMode, setEditMode] = useState<'vector' | 'bitmap'>('vector')`
- `bitmapCanvasRef` — ref to the HTML5 canvas element for bitmap editing
- `bitmapCtxRef` — the 2D context
- Bitmap drawing state refs: `isBitmapDrawing`, `bitmapLastPoint`

## Feature 3: Reshape Tool

**Goal:** Edit anchor/control points of vector shapes (rect, circle, line).

**Files to modify:**
- `leaplab_frontend/src/components/PaintEditor.tsx` — reshape logic + custom controls

**Approach:**
Fabric.js has built-in custom controls. For reshape mode:
1. When `activeTool === 'reshape'`, enable custom control points on the selected object
2. For `Rect`: Show 4 corner controls + 4 edge midpoint controls for resizing
3. For `Circle`: Show radius control point + position control
4. For `Line`/paths: Show endpoint control points
5. Implementation:
   - Use `fabric.Object.prototype.controls` to set custom controls per object type
   - In reshape mode, set `canvas.selection = false` and make objects selectable with visible controls
   - Controls are already part of Fabric.js — just need to ensure they're visible and styled

**Simplified approach (pragmatic):**
- When reshape tool is active, set the selected Fabric.js object's `controls` to show all 8 resize handles (corners + edges) with larger hit areas
- Set `object.setControlsVisibility({ mtr: true })` for rotation handle
- The key change: in reshape mode, objects get `transparentCorners: false` and larger corner controls (12px) so users can drag individual corners
- For non-rect shapes, Fabric.js handles this natively — the existing controls already allow reshaping

## Feature 4: Rotation Center

**Goal:** Let users set a custom rotation center per costume. The sprite rotates around this point.

**Files to modify:**
- `leaplab_frontend/src/stage/Sprite.ts` — add rotationCenterX/Y to Costume interface
- `leaplab_frontend/src/components/PaintEditor.tsx` — UI to set rotation center
- `leaplab_frontend/src/stage/Stage.tsx` — use rotation center in rendering (read Sprite.ts render method)
- `leaplab_frontend/src/stage/CostumesTab.tsx` — pass rotation center through

**Approach:**

### Data Model (Sprite.ts)
```ts
export interface Costume {
    name: string;
    image: HTMLImageElement;
    width: number;
    height: number;
    rotationCenterX?: number;  // normalized 0-1, default 0.5 (center)
    rotationCenterY?: number;  // normalized 0-1, default 0.5 (center)
}
```

### PaintEditor UI
- Add a "Set Rotation Center" button in the toolbar (or as a checkbox/toggle)
- When active, show a crosshair marker on the canvas that the user can drag
- The marker position is saved as normalized coordinates (0-1) relative to the canvas
- On save, pass the rotation center coordinates through the `onSave` callback
- Update `onSave` signature: `onSave(imageData, svgData?, name?, rotationCenter?: {x: number, y: number})`

### Sprite.ts — addCostume
Update `addCostume` to accept optional rotation center:
```ts
async addCostume(name: string, src: string, rotationCenter?: {x: number, y: number}): Promise<void>
```
Default to `{x: 0.5, y: 0.5}` if not provided.

### Sprite.ts — render()
Current code (line 796): `ctx.drawImage(costume.image, -w/2, -h/2, w, h)`
Change to use rotation center offset:
```ts
const rcx = (costume.rotationCenterX ?? 0.5) * w;
const rcy = (costume.rotationCenterY ?? 0.5) * h;
ctx.drawImage(costume.image, -rcx, -rcy, w, h);
```

### IntermediateApp / JuniorApp
When saving from PaintEditor, extract the rotation center and pass it to `sprite.addCostume()` or update the costume's rotation center.

## Feature 5: Eyedropper Tool

**Goal:** Pick a color from anywhere on the canvas by clicking.

**Files to modify:**
- `leaplab_frontend/src/components/PaintEditor.tsx` — eyedropper tool logic
- `leaplab_frontend/src/components/HSBColorPicker.tsx` — enable the eyedropper button

**Approach:**
1. Add `eyedropper` as a valid tool in `activeTool`
2. Add an Eyedropper tool button in the drawing tools panel (next to Fill, or replace the Reshape button's position)
3. When eyedropper is active:
   - Change cursor to a crosshair or custom eyedropper cursor
   - On canvas click, get the pixel color at that point:
     ```ts
     const pointer = canvas.getScenePoint(opt.e);
     const pixel = ctx.getImageData(pointer.x, pointer.y, 1, 1).data;
     const hex = '#' + [pixel[0], pixel[1], pixel[2]].map(v => v.toString(16).padStart(2, '0')).join('');
     ```
   - Set the picked color as `fillColor` or `outlineColor` (depending on which picker is active, or default to fillColor)
   - Switch back to `select` tool after picking
4. In HSBColorPicker.tsx, enable the eyedropper button — when clicked, it should activate the eyedropper tool in PaintEditor. This requires passing a callback prop.

**HSBColorPicker changes:**
- Add `onEyedropper?: () => void` prop
- Enable the button (remove `opacity-50 cursor-not-allowed`)
- When clicked, call `onEyedropper()` which sets `activeTool` to `'eyedropper'` in PaintEditor
