# Fix: Project Persistence Bug (Template Stale Data)

## Problem
When user creates a "Fruit Classifier" from template, adds samples, goes back to home, then creates a fresh "Image Classifier" — it loads the old Fruit Classifier data instead of starting fresh.

## Root Cause
`useNeuraProject.ts` line 43: localStorage key is `neura-project-${type}` (e.g., `neura-project-image-classifier`). Both the Fruit Classifier template and fresh Image Classifier use the same type, so they share the same localStorage key. The hook always loads the saved project regardless of whether it's a new project or a resume.

## Fix

### File: `src/components/neura/hooks/useNeuraProject.ts`

**Change the localStorage loading logic** to only resume a saved project if the name matches what's being requested:

```typescript
const [project, setProject] = useState<NeuraProject>(() => {
    const defaultName = getDefaultName(type)
    const requestedName = projectName || defaultName

    const saved = localStorage.getItem(`neura-project-${type}`)
    if (saved) {
        try {
            const parsed = JSON.parse(saved) as NeuraProject
            // Only resume if saved project matches the requested project
            const savedMatchesRequest =
                parsed.type === type &&
                parsed.classes &&
                (parsed.name === requestedName || parsed.name === defaultName)

            if (savedMatchesRequest) {
                // Update name if template provides a specific name
                if (projectName && parsed.name === defaultName) {
                    return { ...parsed, name: projectName, updatedAt: Date.now() }
                }
                return parsed
            }
        } catch {
            // Invalid data, create new
        }
    }

    // Create fresh project
    return {
        id: generateId(),
        type,
        name: requestedName,
        classes: [],
        createdAt: Date.now(),
        updatedAt: Date.now(),
        modelTrained: false,
        accuracy: undefined
    }
})
```

### Logic:
1. If saved project exists AND its name matches the requested name → **resume** it
2. If saved project exists BUT name doesn't match (e.g., saved "Fruit Classifier", requesting fresh "My Image Classifier") → **create new**
3. If no saved project → **create new**

### Flow:
- User creates "Fruit Classifier" template → saves as `neura-project-image-classifier` with name "Fruit Classifier"
- User goes back, clicks fresh "Image" card → requested name is "My Image Classifier", saved name is "Fruit Classifier" → **mismatch → create new project**
- User goes back, clicks "Fruit Classifier" template again → requested name matches saved → **resume existing project**

## Verification
1. Create Fruit Classifier → add samples → go back
2. Click fresh Image Classifier → should show empty project with default name
3. Go back → click Fruit Classifier template again → should resume with samples intact
4. Force reload → Fruit Classifier data should persist
